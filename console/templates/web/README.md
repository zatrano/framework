# __APP_NAME__

ZATRANO web application generated by `zatrano new --web` (scaffold __SCAFFOLD_NAME__).

HTML defaults with `view`, `assets`, `localization`, and `health`. The same application can take on API presentation later:

```bash
go run ./cmd/app add:api
```

```bash
cp .env.example .env
go run ./cmd/app key:generate
go run ./cmd/app serve
```

Add optional packages from `github.com/zatrano/packages` with `go run ./cmd/app package:enable <name>`. That updates `bootstrap/enabled.go`, writes a blank-import in `bootstrap/addons.go`, runs `go get`, and merges that package's environment keys into `.env.example`. `bootstrap.App()` boots Enabled ∩ Imported. Views live in `app/views`, locales in `app/localization`, and migrations in `app/database`.

A database is optional. After `package:enable database`, link a driver with `go run ./cmd/app db:setup --drivers=sqlite` (or `mysql`, `pgsql`, …).

HTTP is not served until Bootstrap completes (`Booted`). Until then the kernel responds `503`. Generated `/up` is process liveness after Bootstrap. Enabled `health` adds `/health` and `/api/health`. `LifecycleProvider.Start` (workers) runs only after `Start()` (`Running`). `SIGINT`/`SIGTERM` on `serve` stop HTTP then providers in reverse order.
