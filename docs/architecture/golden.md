# Golden application scenarios

Phase 2 evidence: these scenarios prove the accepted STANDARD is sufficient to build realistic ZATRANO applications. They are **test domains**, not new framework features. They remain the canonical examples under the Phase 4 freeze.

Do not implement a demo app inside the framework tree. Copy this shape into a consumer created by `zatrano new --full`.

**Canonical stack (every scenario):**

```text
Route → Middleware → FormRequest → Controller
  → Service (only when §H says so)
  → orm.* / pkg.From(app)
  → View | JSON | Redirect
```

Rejected: UseCase, Action, DTO, Entity, DomainService, mandatory Repository, Handler, UnitOfWork, HTMX, WebService/ApiService.

ADRs: 0001–0008 (Phase 0) plus **0009** (dual controllers) and **0010** (`unique`/`exists` fail-closed as of Phase 4.5; historically documented as fail-open).

## Shared placement

| Concern | Path | Name |
|---|---|---|
| Web controller | `app/http/controllers/web/{resource}_controller.go` | `{Resource}Controller` package `web` |
| API controller | `app/http/controllers/api/{resource}_controller.go` | `{Resource}Controller` package `api` |
| FormRequest | `app/http/requests/{resource}_{intent}_request.go` | `{Resource}{Intent}Request` |
| Model | `app/models/{resource}.go` | `{Resource}` + `Fillable()` |
| Policy | `app/policies/{resource}_policy.go` | `New{Resource}Policy() *authorization.Policy` |
| Service | `app/services/{name}_service.go` | `New{Name}Service()` + verb method |
| Web routes | `app/routes/web/{resources}.go` | `Register{Resources}(r *routing.Router)` |
| API routes | `app/routes/api/{resources}.go` | same, JSON only |
| Views | `app/views/{resources}/{index,create,show,edit}.html` | `http.View("…")` |
| HTTP tests | `tests/http/{resource}_test.go` | `packages/testing.TestCase` |
| Service tests | `tests/services/{name}_test.go` | only when a service exists |
| Policy tests | `tests/policies/{resource}_policy_test.go` | Gate `Allows`/`Denies` |
| Migration | `app/database/migrations/*_{table}.go` | unique/indexes live **here**, not on the struct |

**Policy registration (exact API):**

```go
gate := authorization.From(app)
gate.Policy("post", policies.NewPostPolicy())
err := gate.Authorize(user, "post.update", post)
```

Ability strings are `{policyName}.{ability}` (`post.view`, `post.create`, `post.update`, `post.delete`). `make:policy` emits `view` / `update` / `delete`; add `Define("create", …)` when Store needs it.

**403 mapping:**

| Transport | On `Authorize` error |
|---|---|
| API | `authorization.ResponseFor(err)` — always JSON 403 |
| Web | `http.Abort(403, err.Error())` — do **not** use `ResponseFor` (it is JSON-only) |

**PUT and PATCH** both bind `{Resource}UpdateRequest` and call `Update`. There is no `PatchRequest`.

**IndexRequest:** required on every index that accepts query parameters, including `page`, `q`, `sort`, and filters. Skip only a static list with no query string.

**Destroy:** no FormRequest. Path id + Policy.

**Constructor:** empty struct, or fields assigned at route registration (`PostController{Orders: NewOrderPlacementService()}`). No container autowire.

**Repository:** none of these scenarios require one. Default is `orm.Query[T]()`. A concrete `app/repositories` wrapper is optional only when a test fake of persistence is needed without a second architecture.

## 1. User

Model: `app/models/user.go` — generated by `make:auth`, then given `Fillable()`. Identity for session/API; not a DDD entity.

| Concern | Canonical |
|---|---|
| Fields | `orm.Model`; `Name`; `Email`; password hash column **not** in Fillable |
| Fillable | `[]string{"name", "email"}` — never raw password |
| Create | Registration: `RegisterRequest` → `auth` registrar / hashing — not `orm.Create` of a plaintext password |
| Update | `ProfileUpdateRequest` or admin `UserUpdateRequest` |
| Auth relationship | Session guard `auth.From(app)`; PAT via `apitoken` |
| Ownership | `user.AuthID()` compared in policies of Post/Order/File |
| Validation | email unique **only if** `database` enabled (ADR-0010) |
| Index/filter | admin `UserIndexRequest` (`q`, `page`) |
| Pagination | `Query[User]().OrderByDesc("id").Paginate(page, 15)` |
| Web | `web.UserController` or generated profile methods on `AuthController` |
| API | `api.UserController` for admin/resource; auth endpoints stay on generated auth routes |
| AuthZ | `NewUserPolicy()`; admin list is `user.view`; a user may update self |
| Tests | `tests/http/auth_test.go` (generated flows) + `tests/http/user_test.go` for admin CRUD |

Do not invent `UserRepository` or `UserDTO`. Password change uses generated `ChangePassword` + `ChangePasswordRequest`, not mass assignment.

## 2. Blog / Post — full CRUD

Enable: `validation`, `database`, `orm`, `view` (web), `authorization`, `auth`.

**Files**

| Piece | Path | Type |
|---|---|---|
| Model | `app/models/post.go` | `Post` |
| IndexRequest | `app/http/requests/post_index_request.go` | `PostIndexRequest` |
| StoreRequest | `app/http/requests/post_store_request.go` | `PostStoreRequest` |
| UpdateRequest | `app/http/requests/post_update_request.go` | `PostUpdateRequest` |
| Web controller | `app/http/controllers/web/post_controller.go` | `PostController` |
| API controller | `app/http/controllers/api/post_controller.go` | `PostController` |
| Policy | `app/policies/post_policy.go` | `NewPostPolicy` |
| Service | **none** | single-model writes |
| Web routes | `app/routes/web/posts.go` | |
| API routes | `app/routes/api/posts.go` | |
| Views | `app/views/posts/{index,create,show,edit}.html` | |
| Tests | `tests/http/post_test.go` | web + API cases in one file or `post_api_test.go` sibling |

**Model**

```go
type Post struct {
    orm.Model
    UserID     uint64 `db:"user_id"`
    CategoryID uint64 `db:"category_id"`
    Title      string `db:"title"`
    Body       string `db:"body"`
}
func (Post) Fillable() []string { return []string{"user_id", "category_id", "title", "body"} }
```

Set `user_id` from `auth` user in the controller after validation — never from a client-trusted body field for ownership. If the field is fillable, strip it from `validated` before Create or overwrite after.

### Operation trace

| Verb | Route file | MW | Request | AuthZ | Controller method | ORM | Response | Test |
|---|---|---|---|---|---|---|---|---|
| GET index | web/posts.go `GET /posts` | optional auth | `PostIndexRequest` | `post.view` optional for public list | `Index` | `Query[Post]().Where…Paginate` | `http.View("posts/index", …)` | 200, empty state, 422 bad sort |
| GET create | web `GET /posts/create` | auth | none | `post.create` | `Create` | none | `http.View("posts/create")` | 200 / 401 |
| POST store | web `POST /posts` | auth, CSRF | `PostStoreRequest` | FormRequest `Authorize` + `post.create` | `Store` | `orm.Create[Post](attrs)` | `Redirect` named `posts.show` | 302, 422, 403 |
| GET show | web `GET /posts/{id}` | — | none | `post.view` after Find | `Show` | `Find[Post](id)` | `http.View("posts/show")` | 200 / 404 / 403 |
| GET edit | web `GET /posts/{id}/edit` | auth | none | `post.update` after Find | `Edit` | `Find` | `http.View("posts/edit")` | owner 200; other 403 |
| PUT/PATCH update | web `PUT\|PATCH /posts/{id}` | auth, CSRF | `PostUpdateRequest` | `post.update` after Find | `Update` | `Query[Post]().Where("id", id).Update(attrs)` | `Redirect` `posts.show` | 302, 422, 403 |
| DELETE destroy | web `DELETE /posts/{id}` | auth, CSRF | none | `post.delete` after Find | `Destroy` | `Query[Post]().Where("id", id).Delete()` | `Redirect` `posts.index` | 302, 403 |

API (no Create/Edit views):

| Verb | Route | Request | Method | Response |
|---|---|---|---|---|
| GET `/api/v1/posts` | `PostIndexRequest` | `Index` | `http.JSON` `{data, meta}` |
| POST `/api/v1/posts` | `PostStoreRequest` | `Store` | `http.JSON` 201 |
| GET `/api/v1/posts/{id}` | none | `Show` | `http.JSON` 200 |
| PUT/PATCH `/api/v1/posts/{id}` | `PostUpdateRequest` | `Update` | `http.JSON` 200 |
| DELETE `/api/v1/posts/{id}` | none | `Destroy` | `http.JSON` 204 or `{ok:true}` |

API CSRF: excluded (`csrf.Except("/api")`). Auth: `apitoken` or session per product; golden API uses token middleware on the group.

**Validation location:** only FormRequest `Rules()`. **Authorization location:** FormRequest `Authorize` (coarse) then `gate.Authorize` after Find for ownership (IDOR).

**NO SECOND WAY:** do not put rules in the controller; do not add `PostService` for this CRUD; do not use `jsonapi` unless the product opts in (ADR-0008).

## 3. Category + relationships

Models: `Category`, `Post` (`category_id`).

| Concern | Canonical |
|---|---|
| Declaration | No relation tags. Call ORM functions with **explicit FK** |
| Category → Posts | `orm.HasMany[Category, Post](&cat, "category_id")` |
| Post → Category | `orm.BelongsTo[Post, Category](&post, "category_id")` |
| Eager | `Query[Category]().With(orm.EagerHasMany[Category, Post]("Posts", "category_id"))` |
| Create through relation | **Not a special API.** `orm.Create[Post]({category_id, …})` |
| Update relation | Update `category_id` via `PostUpdateRequest` + `exists:categories,id` |
| Delete relation | Set FK null if nullable, or delete child rows; no `Dissociate()` helper required |
| Filter | `PostIndexRequest` field `category_id` → `Where("category_id", id)` |
| AuthZ across relation | Creating a Post: `category` must be visible; Policy may load Category and deny |
| Tests | `tests/http/category_test.go`; eager-load count; FK filter |

**String eager `With("posts")` is NOT SUPPORTED.**

### Other ORM relation primitives (source-backed)

Use only when the domain needs them. Do not invent wrappers.

| Primitive | ORM API | Application usage |
|---|---|---|
| HasMany | `HasMany`, `EagerHasMany`, `LoadHasMany` | Category → Posts |
| HasOne | `HasOne` + eager/load | User → Profile if a Profile model exists |
| BelongsTo | `BelongsTo` | Post → Category, Order → User |
| BelongsToMany | `BelongsToMany`, `Attach`/`Detach`/`Sync`/`Toggle` | Post ↔ Tag; pivot extras via `Attach` maps |
| Through | `HasManyThrough`, `HasOneThrough` | User → Posts through a team, if modeled |
| Morph* | `MorphTo`, `MorphToByTable`, `MorphToMany`, `MorphedByMany`, `AttachMorph` | Optional Comment on Post/Product — **only if** the app has a morph column pair |
| Nested eager | `Nested`, `Then` | Category → Posts → User |
| Existence | `WhereHas`, `WhereDoesntHave` | Categories that have posts |
| Counts | `WithCount`, `CountRelated` | `posts_count` on index |

Unsupported as application architecture: inferred FK without arguments as the *documented* style (always pass FK); relation struct tags; Laravel-style association `Create`.

If STANDARD were silent on Attach/Sync, that would be a gap — it is specified in STANDARD §L. Application-level “create through HasMany” remains **Create with FK**, not a missing ORM method to invent.

## 4. Product

| Concern | Canonical answer |
|---|---|
| Numeric | `Price` int/decimal column; validate `required|numeric` |
| Nullable | pointer or `WhereNull`; request `nullable` |
| Defaults | `Defaults() map[string]any` on the model (`HasDefaults`) and/or `PrepareForValidation` |
| Unique | migration `Unique("sku")` **and** rule `unique:products,sku` **only with database** |
| Indexes | **migrations only** — not model struct tags |
| Filter/sort/page | **always** `ProductIndexRequest` |
| Validation | FormRequest; uniqueness is not AuthZ |
| Update | `ProductUpdateRequest`; unique ignore current id if the rule supports it — otherwise service-invariant after validate |
| AuthZ | `NewProductPolicy()`; public catalog may skip auth on Index/Show |
| Database down | unique/exists **pass** without checker (ADR-0010) — correctness limitation, not a security control |

No ProductService for CRUD. No repository.

## 5. Order (multi-write)

```text
User → Order → OrderItem → Product
```

This is the scenario that **forces** a service.

| Piece | Canonical |
|---|---|
| Models | `Order`, `OrderItem` (`order_id`, `product_id`, `qty`, `price`) |
| Request | `OrderStoreRequest` — dotted keys `items.0.product_id`, `items.0.qty` |
| AuthZ | `order.create` (authenticated owner); products must be purchasable |
| Controller | `web.OrderController.Store` / `api.OrderController.Store` — **no** `orm.Transaction` |
| Service | `OrderPlacementService.Place(input) (*models.Order, error)` **mandatory** |
| TX | `orm.Transaction` inside `Place`; `QueryTx` for Order, OrderItem, Product stock |
| Rollback | return error from the fn; panic rethrown by ORM |
| After commit | `notification.From(app).Send` or `queue` job — **never inside** the TX |
| Loading | `With(EagerHasMany[Order, OrderItem]("Items", "order_id"))` |
| Tests | `tests/services/order_placement_test.go` (stock failure → no order row); HTTP 422/403 in `tests/http/order_test.go` |

**When Service is mandatory (deterministic):**

| Condition | Service |
|---|---|
| More than one model write | **Yes** |
| Explicit transaction | **Yes** |
| Reuse from HTTP and console/job | **Yes** |
| Orchestration of several packages beyond one `From` call | **Yes** |
| Single-model CRUD | **No** |

Do not add UnitOfWork. Do not add OrderRepository. Controller may construct `NewOrderPlacementService()` at registration.

## 6. File

Domain is **file metadata + disk bytes**, not image processing.

| Step | Canonical |
|---|---|
| Request | `FileUploadRequest` or `StoredFileStoreRequest` — file required, mime, max size |
| Validation | FormRequest file rules |
| AuthZ | `file.create` before store; `file.view` / `file.delete` before download/delete |
| Storage | `filesystem.From(app)` — `Put` / `PutFile` on disk `local` / `public` / `s3`; paths via kernel `safepath` (package uses it) |
| Filename | generated (uuid) — never raw user filename as the disk path |
| Metadata | `models.File` (or `StoredFile`) — `path`, `disk`, `mime`, `size`, `user_id` |
| Ownership | `user_id` from auth, not from the body |
| Replacement | delete old disk object then Put; same row Update — two writes ⇒ small service **or** sequential in controller if not atomic; **if both DB+disk must roll back together, use a service** and accept disk orphan as a documented limitation (no distributed TX) |
| Download | authorized controller; `Get` then response bytes; private disks are not under `public/` |
| Deletion | Policy then disk `Delete` then ORM Delete |
| Failure | validation 422; authz 403; disk error 500 + report |
| Tests | traversal rejected; unauthorized download 403; owner 200 |

**NOT SUPPORTED:** image-processing pipeline, extra storage packages, HTMX upload widgets as architecture.

Replacement without a transaction is acceptable when the product documents orphans; do not invent a UnitOfWork.

## 7. Authentication

Follow **generated** `make:auth`. Do not redesign.

| Flow | Web route (stub) | Request | Controller |
|---|---|---|---|
| Register form | `GET /auth/register` | — | `RegisterForm` |
| Register | `POST /auth/register` | `RegisterRequest` | `Register` |
| Login form | `GET /auth/login` | — | `LoginForm` |
| Login | `POST /auth/login` | `LoginRequest` | `Login` |
| Logout | `POST /auth/logout` | — | `Logout` |
| Forgot | `GET/POST /auth/forgot-password` | `ForgotPasswordRequest` | `ForgotForm` / `Forgot` |
| Reset | `GET/POST /auth/reset-password` | `ResetPasswordRequest` | `ResetForm` / `Reset` |
| Change password | `GET/POST /auth/password/change` | `ChangePasswordRequest` | `ChangePasswordForm` / `ChangePassword` |
| MFA challenge | `/auth/two-factor-challenge` | challenge request | `TwoFactorChallenge*` |
| MFA enable/disable | `/auth/user/two-factor/*` | auth MW | `EnableTwoFactor` … |
| Profile | `/auth/profile` | `ProfileUpdateRequest` | `ProfileForm` / `UpdateProfile` |
| Verify email | `/auth/email/verify/{id}` | — | `Verify` |

API (`RegisterAuthAPI`): `/api/v1/auth/login|register|…` on the **same** `web.AuthController` with `WantsJSON()` — **ADR-0009 exception**. Throttle: `ratelimit` named `login`.

Session: auth session guard. API tokens: `apitoken` middleware, not cookies. Guest MW: `auth.RedirectIfAuthenticated`. Authenticated groups: `auth.Middleware`.

Tests: `tests/http/auth_test.go` — wrong password, CSRF on web POST, MFA reject, no password in logs.

Dashboard RBAC stubs are **not** this flow (ADR-0006).

## 8. Authorization (User, Post, Order)

| Question | Answer |
|---|---|
| Who? | Authenticated user from `auth.From(app)` / middleware |
| Where? | FormRequest `Authorize` (HTTP) then `gate.Authorize` after `Find` (resource) |
| When? | Before mutate and before leaking private representations |
| API? | `authorization.From(app)` → `*Gate`; `Policy("post", NewPostPolicy())`; abilities `post.update` |
| Failure? | Guest: 401 middleware. Missing row: 404. Authenticated forbidden: 403 |
| IDOR? | Never trust body `user_id`. Compare `user.AuthID()` to `post.UserID` / `order.UserID` |
| Dashboard stubs? | UI only — **not** Gate |

Do not invent a third system.

## 14. Query taxonomy

**Supported (use these):** `Query`, `Where`/`OrWhere` family, `OrderBy`/`Latest`, `Limit`/`Offset`/`ForPage`, `Paginate`/`SimplePaginate`, `With(loader)`, `Find`/`FindOrFail`/`First`/`Get`, `Create`, `Update`/`Delete` on Querier, `InsertMany`, `Upsert`, aggregates (`Count`/`Sum`/…), `WhereExists`/`WhereHas`, `QueryTx` + `Transaction`, `WhereRaw` (bound args).

**Unsupported (do not fabricate):** cursor/keyset pagination as a page API, query `context.Context`, nested TX/savepoints, typed `ErrModelNotFound`, `With("name")`.

## 15. Directory fit

Every scenario above fits STANDARD §C. **No new architectural directory is required.** That is the directory audit: PASS.

Optional dirs already in the tree: `repositories`, `resources`, `jobs`, `notifications`, `policies`. Golden apps use `policies` and `notifications` when those packages are enabled; they do not invent `domain/`.

## AI determinism (six requirements)

| Requirement | Same structure? | Notes |
|---|---|---|
| Product CRUD | **YES** | IndexRequest; no service; dual controllers if both transports |
| Category/Post relationship | **YES** | explicit FK; Create with `category_id`; EagerHasMany |
| Order atomic writes | **YES** | `OrderPlacementService.Place` + `orm.Transaction` |
| Authenticated user’s Post | **YES** | `user_id` from auth; `post.update` Policy |
| File upload with ownership | **YES** | UploadRequest; filesystem; metadata model; Policy |
| API equivalent of Post CRUD | **YES** | `controllers/api`; JSON; same requests/policies |

Ambiguities closed by this document + ADR-0009/0010: Policy fluent vs method-style; IndexRequest when only `page`; Web/API mix; unique/exists database-backed semantics (fail-closed, Phase 4.5); auth stub exception.
